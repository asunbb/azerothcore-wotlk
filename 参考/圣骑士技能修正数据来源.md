## 1. 修正机制总览

圣骑士的修正分为 **3 个实现层**：

| 层 | 说明 | 典型入口 |
|---|---|---|
| **代码驱动** | 在 `spell_paladin.cpp` / `Unit.cpp` / `SpellEffects.cpp` 中有显式 C++ 逻辑 | 见各章节 `file:line` |
| **数据库驱动** | 系数写在 `spell_bonus_data` 表中，由通用引擎读取 | `Unit::SpellDamageBonusDone` `Unit.cpp:8847`、`SpellHealingBonusDone` `Unit.cpp:9604` |
| **DBC 数据驱动** | 天赋/套装/雕文的光环（`ADD_PCT_MODIFIER` / `MOD_DAMAGE_PERCENT_DONE` 等）写在 spell DBC 中，由通用引擎应用，**源码中无对应脚本** | `SpellPctDamageModsDone` `Unit.cpp:8401`、`SpellDoneCritChance` `Unit.cpp:9085` 等 |

> 标注 **DBC** 的条目表示该修正是纯数据驱动，搜索源码不会有结果。本文会明确区分。

### 正义圣印详细公式

```cpp
float ap   = GetTarget()->GetTotalAttackPowerValue(BASE_ATTACK);
int32 holy = GetTarget()->SpellBaseDamageBonusDone(SPELL_SCHOOL_MASK_HOLY)
           + eventInfo.GetProcTarget()->SpellBaseDamageBonusTaken(SPELL_SCHOOL_MASK_HOLY);
if (AuraEffect* e = GetTarget()->GetDummyAuraEffect(SPELLFAMILY_PALADIN, 2025, EFFECT_0))
    holy += e->GetAmount();                              // Libram of Divine Purpose
int32 bp = max(0, int32((ap*0.022f + holy*0.044f) * GetTarget()->GetAttackTime(BASE_ATTACK) / 1000));
```
位置：`spell_paladin.cpp:1202-1211`。注释：`${$MWS*(0.022*$AP+0.044*$SPH)}`。

### 神圣庇护（Sacred Shield）完整公式

```cpp
float bonus = CalculatePct(caster->SpellBaseHealingBonusDone(schoolMask), 75.0f);  // +75% SP 治疗

bonus *= caster->CalculateLevelPenalty(GetSpellInfo());                            // 等级惩罚
amount += int32(bonus);
// 竞技场 Dampening
if (AuraEffect* d = GetAuraEffect(74410/74411, EFFECT_0)) AddPct(amount, d->GetAmount());
// ICC 增益(1704/937 EFF_2 MOD_HEALING_DONE_PERCENT)
if (AuraEffect* s = GetAuraEffect(MOD_HEALING_DONE_PERCENT, GENERIC, 1704/937, EFFECT_2)) AddPct(amount, s->GetAmount());
```

## 11. 关键结论

1. **物理近战核心**（十字军打击、神圣风暴、正义之锤、正义盾击）**不吃法术强度**，
   只吃武器伤害 / AP / 格挡值 + 天赋百分比修饰。
2. **神圣系伤害**（奉献、驱邪、神圣愤怒、审判等）走 `spell_bonus_data` 表的 **AP + SP 双系数**。
3. **治疗系**（圣光、圣光闪现、神圣震击治疗）走 `spell_bonus_data` 表的纯**治疗强度**系数。
4. 大量**天赋百分比 / 套装 / 雕文**修正是 **DBC 数据驱动**（`ADD_PCT_MODIFIER` /
   `MOD_DAMAGE_PERCENT_DONE` 等），通过通用引擎 `Unit.cpp` 的
   `SpellPctDamageModsDone` / `SpellDamageBonusDone` / `SpellPctHealingModsDone` 应用，**源码中无对应脚本**。
5. `Unit::SpellDamageBonusDone` / `SpellHealingBonusDone` / `SpellDoneCritChance` 等
   通用加成函数中**没有任何** `SPELLFAMILY_PALADIN` 专属分支；圣骑士的特殊逻辑集中在
   `spell_paladin.cpp` 与 `SpellPctDamageModsDone`(8656)、`SpellTakenCritChance`(9272) 两个点。


## 14. 附录：施法时间（Cast Time）与 `Spell::cast` 的调度关系

本节梳理通用法术系统中「施法时间」如何决定 `Spell::cast` 的调用时机与参数，
也是第 8 章（天赋施法时间缩减）和前文 `cast`/`_cast`/`GetSpellModOwner` 三函数的串联说明。

### 14.1 施法时间的计算（`m_casttime` 的来源）

施法时间在 `Spell::prepare` 中一次性算定，之后不再改变。

**入口** `SpellInfo::CalcCastTime(caster, spell)`（`SpellInfo.cpp:2752`）：

```
基础值 = CastTimeEntry->CastTime          // 来自 SpellCastTimes.dbc
+ 500ms   若 SPELL_ATTR0_USES_RANGED_SLOT（非自动射击）
→ caster->ModSpellCastTime(this, castTime, spell)   // 应用修饰
→ max(castTime, 0)
```

**修饰** `Unit::ModSpellCastTime`（`Unit.cpp:11728`）两层修饰：

1. **玩家 SpellMod**：`ApplySpellMod(SPELLMOD_CASTING_TIME)` ——
   应用天赋/雕文/套装的施法时间缩减。通过 `GetSpellModOwner()` 取得归属玩家（见第 8 章
   施法时间相关天赋与本函数的关联）。
2. **按 DmgClass 的急速缩放**：

| DmgClass | 处理 |
|---|---|
| `MAGIC` | `× UNIT_MOD_CAST_SPEED`（急速），或 `CanInstantCast()` → 0 |
| `RANGED` | `× 远程攻击速度百分比` |
| `NONE` | 周期急速（`SPELL_ATTR5_SPELL_HASTE_AFFECTS_PERIODIC`）或烹饪特例 |
| `MELEE` | 不变 |

**赋值**（`Spell.cpp:3529`）：

```cpp
m_casttime = HasTriggeredCastFlag(TRIGGERED_CAST_DIRECTLY) ? 0
            : m_spellInfo->CalcCastTime(m_caster, this);
if (CHEAT_CASTTIME) m_casttime = 0;        // 作弊模式强制瞬发
```

随后 `ReSetTimer()` → `m_timer = m_casttime`（`Spell.h:565`），即**计时器初值 = 施法时间**。

### 14.2 `prepare` 中根据施法时间分流到 `cast()`

`prepare` 末尾对 `m_casttime` 有 **3 条路径**：

| 条件 | 行为 | 代码位置 |
|---|---|---|
| `TRIGGERED_CAST_DIRECTLY`（且非引导） | **立即** `cast(true)` | `Spell.cpp:3618` |
| `m_casttime == 0`（瞬发通用法术） | **立即** `cast(true)` | `Spell.cpp:3662` |
| `m_casttime > 0`（有施法时间） | 注册为 `SetCurrentCastedSpell` + `SendSpellStart`（发施法条），**等待计时** | `Spell.cpp:3637-3638` |

> 即：**瞬发法术在 `prepare` 内同步调用 `cast()`；有施法时间的法术不立即 cast，
> 进入 `SPELL_STATE_PREPARING` 等待。**

### 14.3 计时到期 → `cast()`（`Spell::update`）

`SpellEvent::Execute`（`Spell.cpp:8318`）每个世界 tick 调用 `Spell::update(p_time)`，
其中 `SPELL_STATE_PREPARING` 分支倒计时：

```cpp
// Spell.cpp:4506-4519
case SPELL_STATE_PREPARING:
    if (m_timer > 0)
        m_timer -= difftime;          // 倒计时
    if (m_timer == 0 && !IsNextMeleeSwingSpell() && !IsAutoRepeat())
        cast(!m_casttime);            // ★ 计时归零，触发施法
    break;
```

**关键点：`cast()` 的实参 `!m_casttime`**

- 瞬发法术（`m_casttime==0`）→ 传 `skipCheck=true`（已在 prepare 校验过，跳过重复 CheckCast）；
- 有施法时间法术（`m_casttime>0`）→ 传 `skipCheck=false`（施法条走完后**需重新 CheckCast**，
  校验距离/视线/法力等是否仍满足，因为施法期间目标可能移动）。

此处还有移动中断检查（`Spell.cpp:4495`）：玩家在 PREPARING 期间移动且有
`SPELL_INTERRUPT_FLAG_MOVEMENT` → `cancel()`。

### 14.4 `_cast` 内部对施法时间的二次依赖

进入 `cast()` → `_cast()` 后，施法时间仍在两处起作用：

1. **近战计时器重置抑制**（`Spell.cpp:4066`）：

   ```cpp
   if (m_casttime == 0 && m_spellInfo->CalcCastTime())
       resetAttackTimers = false;
   ```

   原本有施法时间、但被 spellmod 压到 0 的法术，**不再重置近战计时器**（防止瞬发滥用）。

2. **投射物 vs 立即分支**（`Spell.cpp:4024`）：与 `m_casttime` 无关，取决于
   `m_spellInfo->Speed`（飞行速度），决定走 `SPELL_STATE_DELAYED`（等投射物）还是
   `handle_immediate()`。

### 14.5 完整调度链

```
玩家发起施法
  └─ Spell::prepare
       ├─ m_casttime = CalcCastTime() → ModSpellCastTime (急速 + SpellMod)
       ├─ m_timer = m_casttime
       │
       ├─[瞬发/直接触发] cast(true)  ←──── 同步路径
       │       └─ _cast() 立即执行
       │
       └─[有施法时间] SetCurrentCastedSpell + SendSpellStart
              └─ 注册 SpellEvent，每 tick 调 update()
                     └─ PREPARING: m_timer -= dt
                            └─ m_timer==0 → cast(!m_casttime)  ←──── 异步路径
                                   └─ _cast(skipCheck) 执行
                                          └─ CheckCast (skipCheck=false 时重新校验)
                                          └─ SelectSpellTargets / TakePower / HandleLaunchPhase / ...
```

### 14.6 总结：二者的逻辑关系

1. **施法时间是 `cast()` 的调度闸门**：`m_casttime==0` → `prepare` 内同步调 `cast()`；
   `m_casttime>0` → 等 `m_timer` 倒计时归零后由 `update()` 异步调 `cast()`。
2. **`cast()` 的 `skipCheck` 参数由施法时间派生**：`!m_casttime`。瞬发跳过二次校验，
   有施法时间的法术在进度条结束后重新 CheckCast（应对目标移动等）。
3. **施法时间修饰集中在 `ModSpellCastTime`**，通过 `GetSpellModOwner()` 应用玩家层面的
   天赋/雕文/套装缩减与急速缩放——这把「施法时间」与第 8 章天赋修正、以及
   `GetSpellModOwner` / `cast` / `_cast` 三个函数串成一条完整链路。
4. **`m_casttime` 一旦在 prepare 算定即固定**；中途的「打断/推迟」
   （`Delayed` / `interrupt`，`Spell.cpp:7943`、`7984`）操作的是 `m_timer`（剩余时间），
   不重算 `m_casttime`。
